# Technical Notes

This document captures underlying design decisions, architectural considerations, and implementation details for the `@dashkite/runes` module.

### Capability and Policy-Based Authorization

The underlying architecture of runes is a variant of Cobalt and Web Grant technology, which inherently utilizes a [capability-based security](https://en.wikipedia.org/wiki/Capability-based_security) model. When combined with `@dashkite/enchant`, this capability-based approach forms a robust strategy for constructing comprehensive policy-based authorization schemes.

### Cryptographic Foundation

The module relies on `panda-confidential` for its core cryptographic operations. Runes use a [Message Authentication Code (MAC)](https://en.wikipedia.org/wiki/Message_authentication_code) to prevent tampering. The MAC is generated by hashing the serialization of the authorization, the secret, and a cryptographic nonce. This ensures that even if an attacker alters the authorization data inside the rune, the signature will invalidate it during the verification phase.

### Expiration Management

Rune expiration is managed using `@js-temporal/polyfill` to calculate the precise time bounds. When an `expires` object is passed (e.g., `{ hours: 1 }`), it is converted to a strict [ISO 8601](https://en.wikipedia.org/wiki/ISO_8601) timestamp at issuance. This prevents timezone discrepancies and simplifies the comparison logic during verification.

### Enchant Integration

The `match` function delegates resource and method matching to `@dashkite/enchant`. It evaluates `grants` using `Actions.resource` and `Actions.method`. By leaning on the `enchant` evaluation engine, the matching system remains highly extensible, allowing developers to craft complex rule expressions and dynamic bindings using `Resolvers`.

### Joy Sub-System Usage

The evaluation process uses the `@dashkite/joy` ecosystem (like `generic`, `type`, and `iterable`) to handle generic dispatch and iteration over potentially asynchronous predicates. This allows for flexible evaluation sequences without tightly coupling the module to synchronous constraints.
